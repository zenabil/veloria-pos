# ADR-099 — Audit radical 2026-10-15 : aucun P0 load-bearing, fix UI FR

**Date :** 2026-10-15 · **Statut :** Accepté

## Contexte

Audit radical dossier-par-dossier, fichier-par-fichier ( formattage → typecheck → 726 tests → build → verify-migrations, tous verts ).
Vérifiés : 120 fichiers `src/features/`, 3 `src/application/`, 38 `src/domain/`, 57 `electron/ipc/`, 1 preload (317 lignes), 43 migrations 0001→0043, `src/domain/money/money.ts:1-202`, `electron/ipc/money-guard.ts:13-77`, `electron/ipc/handle.ts:24-94`.

## Décision

1. **Aucune مشكلة load-bearing** : pas de corruption monétaire, pas de perte d'atomicité, pas de drift migrations, pas de fuite IPC, pas de float sur l'argent.
   - `parseFloat` = 0 hit sous `src/`+`electron/` ; `toFixed` = 4 hits tailles Ko/Mo uniquement (`src/shared/formatters/files.ts:8-9`, `src/features/settings/SettingsSectionsB.tsx:746,1331`).
   - `run-sql` = 0 channel (seuls commentaires + garde test `tests/unit/bridge-shape.test.ts:26`).
   - Renderer leaks = 0 hit (`ipcRenderer|better-sqlite3|node:|require('electron')` sous `src/`).
   - `createSaleAtomic` (`electron/ipc/handlers/sales.repo.ts:218`) : FIFO + `UPDATE products.quantity` + `stock_movements sale_out` + `sale_payments` + balance + audit dans UNE seule `db.transaction()`.
   - `verify-migrations.mjs` = `MIGRATIONS VERIFIED`, `integrity_check=ok foreign_key_violations=0`.
2. **`operationId` optionnel sur updates = intentionnel (contrat M-3), pas un bug.** Verrouillé par `tests/unit/update-operationid.test.ts:3-5,21-31` (« idempotent par valeur + audit déterministe ») et `electron/ipc/validators.common.ts:82-86` (hors périmètre volontairement). Ex. `ExpenseDialogs.tsx:224-225` ne l'envoie pas en update — conforme au contrat. Aucun durcissement en requis sans ADR + migration du contrat.
3. **Fix appliqué (P2 UI FR)** : `src/features/stock/dialogs/AdjustmentDialog.tsx:104` `frError(e, "")` → `frError(e, "Ajustement invalide.")`. Motif : `src/shared/errors/fr-map.ts:16` exige un repli FR jamais vide ; avec `""`, une erreur technique rendait un aperçu vide (`"—"`) au lieu d'un message caissier.

## Conséquences

- Pipeline après fix : `prettier --check` OK, `npm run typecheck` OK (`integrity-manifest signé (209 fichiers)`), `vitest` ciblé 4 fichiers / 27 tests OK, `npm run build` OK (`✓ built in 18.79s`), `verify-migrations` OK (`MIGRATIONS VERIFIED`).
- Prochaines cibles P1/P2 (sans migration) : compléter `src/application/` (seuls `sales/create-sale.ts:60-62`, `stock/adjust-stock.ts:35-37`, `customers/client-access.ts:87-89` existent), résidus CHECK couverts par triggers (ex. `stock_movements.quantity_delta` `0001:187-188`), FK implicites NO ACTION (ex. `sales.customer_id` `0001:134`) — chaque changement = nouvelle migration + `verify-migrations` vert, jamais d'édition in-place.
